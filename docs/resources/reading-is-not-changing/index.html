Reading is not changing.

Why a business action needs a different boundary from a query.

On this pageAn answer and an action carry different weightGive a change a declared pathPermission is not the same as approvalStart with the deployment questions

An answer and an action carry different weight

Looking up a product is different from changing its price or sending a sales document to another system. An agent’s ability to understand a request should not decide whether it is allowed to carry it out.

Give a change a declared path

Systead’s current implementation documentation describes declared actions, OPA permission evaluation and a command log. A named business command provides a place to define what may change, under which scope and with which record.

Permission is not the same as approval

A policy can evaluate whether a command is allowed. A human approval is a separate choice about responsibility. Treating every permission check as a person’s approval makes the workflow harder to understand and the record less precise.

Start with the deployment questions

Confirm who can read, who can change, which external destinations are involved and how changes are reviewed. Data location, backup and model access also belong in the deployment conversation. A diagram alone is not evidence that a particular installation enforces every control.
