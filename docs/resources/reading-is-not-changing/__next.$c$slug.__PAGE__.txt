id="section-1"><h2>An answer and an action carry different weight</h2><p>Looking up a product is different from changing its price or sending a sales document to another system. An agent’s ability to understand a request should not decide whether it is allowed to carry it out.</p></section><section class="reading-section" id="section-2"><h2>Give a change a declared path</h2><p>Systead’s current implementation documentation describes declared actions, OPA permission evaluation and a command log. A named business command provides a place to define what may change, under which scope and with which record.</p></section><section class="reading-section" id="section-3"><h2>Permission is not the same as approval</h2><p>A policy can evaluate whether a command is allowed. A human approval is a separate choice about responsibility. Treating every permission check as a person’s approval makes the workflow harder to understand and the record less precise.</p></section><section class="reading-section" id="section-4"><h2>Start with the deployment questions</h2><p>Confirm who can read, who can change, which external destinations are involved and how changes are reviewed.
